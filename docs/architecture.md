# Архитектура

Verso — модульный монолит. Один Next.js процесс обслуживает редактор, серверные страницы чтения и версионированный API. PostgreSQL хранит статьи и служебные данные; приватный S3-compatible Garage хранит изображения, анимации, видео и статичные постеры. Внешний reverse proxy завершает TLS. Порт базы данных и консоль Garage не публикуются в Интернет.

```text
Browser / future native client
              │ HTTPS
              ▼
Reverse proxy (existing Nginx, or standalone Caddy)
              │
              ▼
Next.js app ─────────── PostgreSQL
     │                 articles / versions / ownership digest / reports
     └───────────────── Private S3 storage
                        validated images / animated WebP / MP4 / still posters
```

## Документ и публикация

TipTap / ProseMirror применяет Markdown shortcuts в одном визуальном редакторе. Canonical document — JSON `schemaVersion: 1`; форматирование не восстанавливается из произвольного HTML. Сервер валидирует допустимые узлы, атрибуты, ссылки, глубину и размер документа перед сохранением. Читатель получает безопасный HTML, изображения, таблицы и блоки кода; редактор загружается отдельно от режима чтения.

Внутренний идентификатор записи отделён от публичного случайного Base62 ID из 12 символов. Криптографический генератор и уникальный индекс PostgreSQL защищают от последовательных ID и коллизий; при конфликте генерация повторяется. Обновление сохраняет публичный ID и URL.

Публикация имеет даты создания и обновления, версию, состояние и проверочное представление независимого секрета редактирования. Отдельных пользователей, профилей и социальных сущностей нет. Структура данных и миграции находятся в `prisma/`.

## Анонимное владение

На создании API возвращает секрет ровно автору. PATCH, DELETE и проверка владения получают его через `Authorization: Bearer …`; секрет не попадает в публичный адрес или параметры URL. Сравнение полномочий выполняет сервер. Скрытие Edit — удобство интерфейса, а не контроль доступа.

IndexedDB хранит ключи и черновики на устройстве автора. Это хранилище доступно JavaScript того же origin: защита от XSS, CSP и чистая обработка контента обязательны. IndexedDB не заменяет серверную базу. Очистка данных браузера или потеря устройства без экспорта ключа лишает автора доступа; система не обещает восстановления без ключа.

Версия статьи — optimistic concurrency token. Клиент отправляет текущий `version`; сервер меняет статью атомарно только при совпадении и возвращает 409 при конфликте. Ключ не меняется от обычного обновления.

## Черновики

Черновик сохраняется с debounce в IndexedDB, включая заголовок и документ. Временное отсутствие сети не мешает записи. Начальная загрузка хранилища предшествует автосохранению, чтобы пустое состояние не затёрло сохранённый текст. Изменения между вкладками отслеживаются отдельно от серверных версий; чужое изменение должно показывать уведомление о конфликте, а не молча перезаписывать активный текст.

## Граница доверия

- Входящие документы и JSON проверяются независимо от интерфейса.
- Произвольный HTML не выполняется; опасные протоколы ссылок и неожиданные узлы отклоняются.
- Загрузка проверяет сигнатуру файла, лимит размера и декодированные пиксели; изображение переупаковывается в WebP. Внешний URL не скачивается сервером, что ограничивает SSRF.
- Bearer authorization не использует автоматически прикладываемые cookie. Проверка Origin и JSON content type дополняют защиту изменения данных.
- Лимиты запросов защищают создание, перебор ID, изменение, жалобы и загрузки; reverse proxy должен передавать доверенный адрес клиента и закрывать прямой публичный доступ к приложению.
- CSP, security headers и HTTPS задаются на приложении и reverse proxy.
- Жалобы записываются сервером и требуют операторского процесса рассмотрения; отправленная жалоба не удаляет статью автоматически.

Автор также может вставить внешний HTTPS URL изображения. API сохраняет этот адрес в canonical JSON и безопасном атрибуте `src` обычного `<img>`; сервер не скачивает адрес, не проверяет удалённые пиксели и не передаёт его в прокси оптимизации изображений. Предпросмотр и загрузку опубликованного изображения выполняет браузер. Внешний хост видит запрос читателя и управляет доступностью файла; для хранения внутри Verso предусмотрена отдельная загрузка изображения. HTTP, `data:`, `javascript:`, относительные произвольные адреса и URL с логином/паролем отклоняются. Разрешённые локальные пути ограничены маршрутом загруженных WebP-изображений `/api/v1/media/...`.

Видео по ссылке хранится отдельным узлом `video` с атрибутами `{provider, src}`. Общий URL-normalizer переводит публичные YouTube watch/share/shorts/embed ссылки в `www.youtube-nocookie.com/embed/{id}`, Vimeo — в `player.vimeo.com/video/{id}`, RuTube — в `rutube.ru/play/embed/{id}/`. API принимает только уже нормализованные пары provider/src и не скачивает видео. Vimeo/RuTube ссылки с параметрами доступа не поддерживаются и отклоняются, чтобы не потерять приватный ключ при нормализации. Плееры встроены через iframe с фиксированным заголовком, sandbox и ограниченным CSP `frame-src` по точным хостам. Внешние прямые HTTPS-ссылки на `.mp4`, `.webm` и `.ogv` выводятся как HTML5 `<video controls playsinline preload="metadata">`; их загрузку и воспроизведение выполняет браузер. Сам файл, права доступа, ограничения встраивания и доступность внешнего провайдера остаются за внешним хостом.

## Масштабирование и эксплуатация

Начальная установка рассчитана на один экземпляр приложения. Перед горизонтальным масштабированием нужно проверить общий rate limit state и адаптировать его к нескольким экземплярам. PostgreSQL и S3 уже отделены от процесса приложения. Публичный адрес берётся из `PUBLIC_BASE_URL`; API пригоден для независимых мобильных клиентов.

Мониторинг должен проверять health endpoint, доступность SQL и object storage, HTTP 5xx, свободное место, TLS renewal и срок последнего проверенного backup. Просмотр статьи не зависит от локального ключа владельца. Для восстановления нужны одновременно база, объекты и исходные серверные секреты.

## Обновление медиа и метаданных (17 октября 2026)

Две добавочные Prisma-миграции расширяют Media (`animated`, `frames`, `durationMs`, `posterKey`) и Article (`viewCount`, `showViewCount`, неотрицательное ограничение). Существующие ID, ключи, версии и тексты не переписываются. Постер хранится отдельной записью Media и отдельным S3-объектом; обычный backup охватывает оба. Публикация по-прежнему использует canonical JSON v1 и серверный allowlist-рендер.

Публичная HTML-проекция строится текущим renderer из canonical JSON при чтении. Это даёт старым внешним GIF/потенциальным анимациям новые элементы управления без SQL-обновления статьи; сохранённый html в БД сохраняется. В reader не импортируется TipTap. Контроллер анимаций работает поверх сгенерированных безопасных DOM-элементов; редактор использует отдельный Image NodeView с игнорированием служебных DOM-мутаций, поэтому play/pause не изменяет содержимое или черновик.

Известная загруженная анимация SSR-рендерится статичным постером. Неизвестное внешнее изображение может требовать browser canvas для фиксации кадра; сервер его не скачивает. При reduced motion оно визуально скрыто до готового still canvas; без JS для неизвестного удалённого формата доступен placeholder. Ссылки на сторонние JPEG/AVIF считаются статичными. Сами локальные видео никогда не запускаются автоматически.

Просмотр регистрируется клиентским dwell-событием, а не побочным эффектом чтения SQL. Транзакция блокирует строку статьи, вставляет уникальный краткоживущий токен и атомарно увеличивает агрегат; сырым SQL намеренно не меняет version/updatedAt. ETag публичного API учитывает видимость и открытый count. Закрытое число не сериализуется в HTML, RSC payload или публичные ответы. Поведение и ограничения идентификации описаны в API; это не система уникальных посетителей.

## Editor 2.0

`editor-extensions.ts` собирает ограниченные марки и TipTap-узлы. `editor-block-registry.ts` — единый реестр меню `+` и slash-команд; преобразования и табличные операции выделены в `editor-transforms.ts`. React NodeView хранит исходник формулы/схемы в документе, а служебные панели и подсветка не сериализуются как текст.

`schemaVersion: 1` расширяется добавочно: прежние узлы и необязательные атрибуты продолжают приниматься. Публичный ID и editKeyHash не меняются миграциями. Сервер сохраняет и проверяет canonical JSON; проекция HTML строится при чтении, без массовой перезаписи старых статей.

`reading-tools.tsx` отделён от `writing-tools.tsx`: публичное чтение не импортирует редактор или ProseMirror. KaTeX строит доступную HTML/MathML-проекцию на сервере с отключённым trust и ограничением макросов. Код и Mermaid улучшаются лениво при приближении к viewport. Shiki загружает конкретную грамматику по требованию; блоки свыше 60 000 символов остаются обычным читаемым кодом. Mermaid рендерится последовательно, с ограничением 20 000 символов/500 рёбер и повторной SVG-очисткой; конфигурационные директивы, внешние действия и пользовательский CSS отключены.

IndexedDB версии 2 добавляет snapshots, сохраняя прежние drafts и ownership. Черновая история ограничена 40 снимками на черновик, 30 днями, 200 снимками и 12 MiB всего; не записывается после каждого символа. Повреждённые снимки пропускаются. Восстановление предварительно сохраняет текущую работу. Серверная ArticleVersion ограничена 50 версиями, 90 днями и 16 MiB на статью, очищается в транзакции обновления. Снимок предыдущего текста и изменение текущего состояния коммитятся вместе; устаревший version даёт 409 без фантомного снимка.

Предпросмотр ссылок использует отдельный API с проверкой всех DNS-адресов и pin выбранного публичного IP, проверкой каждого редиректа, лимитами времени/байтов/переходов. Картинка metadata не скачивается сервером. Экспорт HTML/PDF строится отдельно из проверенного JSON; очистка HTML для импорта не используется как способ рендеринга формул и SVG.

Превью медиа — отдельный неизменяемый объект и запись Media. `sourceWidth`/`thumbnailWidth` описывают фактическую ширину, `width` — размер отображения. Анимация не подменяется статичным srcset. Старые объекты не пересоздаются автоматически.
