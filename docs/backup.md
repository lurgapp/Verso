# Резервное копирование и восстановление

Полный архив содержит PostgreSQL custom dump, весь Garage data volume, server `.env` и инфраструктурные конфигурации. В `.env` находятся серверные секреты подключения хранилищ; проверочные SHA-256 значения авторских ключей содержатся в SQL dump. Приватный `garage.toml` также входит в архив. Архив имеет права 600, директория backup — 700; checksum находится рядом. Архив нельзя публиковать, отправлять в открытый bucket или коммитить. Для удалённой копии используйте шифрование и ограниченный доступ.

## Создание

```bash
cd /opt/verso
./scripts/backup.sh
```

По умолчанию создаётся `backups/verso-YYYYMMDDTHHMMSSZ.tar.gz`. Скрипт использует advisory lock, останавливает только Verso app и storage, получает транзакционно согласованный `pg_dump`, копирует остановленное object storage и создаёт SHA-256 checksum. EXIT trap возвращает только ранее работавшие сервисы, включая ошибочный сценарий. База данных остаётся запущенной. Другие проекты сервера не затрагиваются.

Настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| VERSO_PROJECT_DIR | каталог проекта | Compose / .env |
| VERSO_BACKUP_DIR | `$VERSO_PROJECT_DIR/backups` | приватные архивы |
| VERSO_BACKUP_RETENTION_DAYS | 14 | срок локального хранения |
| VERSO_STANDALONE | 0 | 1 для отдельной установки без production override |
| BACKUP_QUIESCE | 1 | 0 отключает остановку; live object snapshot не гарантирует согласованность |

Retention применяется только к архивам `verso-*.tar.gz` в каталоге backup. Копии нужно переносить за пределы VPS: локальная копия не помогает при потере диска или сервера. Секреты и конфигурации reverse proxy / TLS, существующие вне проекта Verso, сохраняются отдельно штатным процессом сервера.

## Восстановление существующей установки

Сначала сохраните текущий backup, архив и checksum, проверьте свободное место, остановите входящий трафик Verso и выберите архив. Restore уничтожает текущую базу и media только этой установки. Не запускайте его в рабочем окружении для простой проверки архива.

```bash
cd /opt/verso
RESTORE_CONFIRM=RESTORE ./scripts/restore.sh /private/verso-YYYYMMDDTHHMMSSZ.tar.gz
```

Скрипт проверяет checksum и архивные пути, останавливает app/storage, сохраняет предыдущий `.env` в приватном каталоге, восстанавливает environment, `garage.toml`, storage и SQL через `pg_restore --single-transaction`, затем пересоздаёт и запускает app/storage для загрузки восстановленной конфигурации. Для очистки только подключённого storage volume используется helper image `alpine:3.22`; предварительно выполните `docker pull alpine:3.22`, если восстановление должно работать без сети. При ошибке сервисы оставляются остановленными для исследования, чтобы частично восстановленные данные не стали публичными. Восстановление PostgreSQL атомарно; media восстановление выполняется отдельным шагом и не является общей транзакцией с SQL.

PostgreSQL database name, user и пароль роли в целевой базе должны соответствовать восстановленному `.env`. `pg_dump` не сохраняет глобальные роли или их пароли. Если секрет базы менялся после даты архива, восстановите совпадающие role credentials либо создайте чистую целевую PostgreSQL установку с архивным `.env`. Не заменяйте пароль без проверки других подключений.

## Новый сервер или изолированная проверка

1. Скопируйте проверенную версию исходного кода и архив вместе с checksum в приватный каталог.
2. Извлеките `environment.env` из доверенного архива в `.env` и `garage.toml` с правами 600. Сохраните исходные credentials хранилища; для изолированного теста смените только адреса и имя Compose проекта.
3. Используйте совместимую версию PostgreSQL 16 и Garage. Поднимите чистые db/storage volumes; не подключайте проверочную установку к volumes рабочей версии.
4. Запустите restore для проверочной установки. При standalone установке задайте `VERSO_STANDALONE=1`.
5. Получите известную статью, сравните её ID, текст и версию; загрузите её изображение; с сохранённым авторским ключом проверьте ownership и Update.
6. Проверьте поведение API с неверным ключом, затем удалите только проверочные containers/volumes.

Backup считается проверенным после фактического восстановления и прикладной проверки, а не после успешного `tar` или checksum. Записывайте дату, выбранный архив, версии сервисов и результат восстановления. Для учения рекомендуется отдельный Compose project без внешней сети production proxy.

## Медиа и статистика

С 17 октября 2026 набор объектов включает Animated WebP, MP4 и отдельные статичные постеры. Копируйте весь Garage volume и соответствующую БД вместе: только основной файл без posterKey/записи Media не является полным восстановлением. Агрегат просмотров и настройка видимости входят в SQL dump. Временные антидубль-токены также могут попасть в защищённый backup; сроки архивного хранения отличаются от их рабочего TTL.

При восстановлении старого архива сначала используйте согласованную с ним сборку/миграции и закрытый входящий трафик. Перед включением обновлённого app примените недостающие добавочные миграции и проверьте старую статью, авторский ключ, обычное изображение, анимацию с постером и video byte range. Не открывайте трафик на новый Prisma client до появления новых столбцов.


История опубликованных версий входит в SQL dump; статичные thumbnail и poster — в Garage volume. Локальные черновики, ключи и их история находятся в IndexedDB устройства и не входят в серверный backup. Для переноса автору нужны экспорт черновика и отдельный файл ключа. Серверный restore не восстанавливает утраченное браузерное хранилище.
