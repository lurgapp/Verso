# API v1

База: `${PUBLIC_BASE_URL}/api/v1`. OpenAPI доступен в `GET /api/v1/openapi`. Релиз редактора 2.0 сохраняет URL API v1 и TipTap JSON `schemaVersion: 1`. Новые узлы и необязательные атрибуты добавлены без изменения старых статей; клиенту не требуется веб-интерфейс Verso.

## Создать статью

`POST /articles`, `Content-Type: application/json`:

```json
{
  "title": "A small story",
  "schemaVersion": 1,
  "content": {
    "type": "doc",
    "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Write. Publish. Share."}]}]
  }
}
```

Ответ 201: `{ "article": { … }, "editKey": "…", "url": "https://…/a/…" }`. Сохраните `editKey` в защищённом клиентском хранилище до завершения процесса публикации. Это ключ владения, независимый от ID статьи. Не добавляйте его в URL, аналитику или журналы.

## Получить и изменить

`GET /articles/{id}` → 200 `{ "article": { … } }`. В публичном ответе нет ключа или его проверочного представления.

`GET /articles/{id}/ownership`, с `Authorization: Bearer <editKey>` → 200 `{ "owner": true }` при действительном ключе.

`PATCH /articles/{id}`, с `Authorization: Bearer <editKey>`, принимает те же `title`, `content`, `schemaVersion` плюс текущий числовой `version`. Ответ 200 возвращает статью с новой версией. ID и публичная ссылка сохраняются. После 409 получите актуальную статью и предложите автору явно объединить или переписать изменения; автоматическая повторная отправка с новой версией может уничтожить чужое обновление.

`DELETE /articles/{id}`, с ключом владельца, удаляет публикацию. Публичный URL после удаления возвращает 404; приватная история этой статьи также удаляется. Независимые резервные копии могут содержать данные в пределах своего срока хранения. Удаление не является способом ротации ключа.

## Изображения и жалобы

`POST /media`, `multipart/form-data`, ровно одно поле `file`. Формат проверяется по содержимому, а не имени или заявленному MIME. Ответ 201 сохраняет совместимое `url` и добавляет `{kind, animated, posterUrl?, thumbnailUrl?, thumbnailWidth?, width, height, frames, durationMs?}`. Поле `posterUrl` переносится в canonical документ как `posterSrc`. Дополнительно создаётся статичное WebP-превью шириной до 480 px: `thumbnailUrl` → `image.thumbnailSrc`, `thumbnailWidth` → `image.thumbnailWidth`, исходный `width` ответа → `image.sourceWidth`. `thumbnailWidth` содержит фактическую ширину превью, которая может быть меньше 480 px. Оригинал и существующие ссылки не заменяются.

| Медиа | Ограничения | Результат |
| --- | --- | --- |
| JPEG/PNG/статичный WebP/AVIF | 8 MiB; 40 млн входных пикселей | WebP со стороной до 2400 px, metadata удалена |
| GIF/Animated WebP/APNG | 8 MiB; 2–240 кадров; до 4 млн пикселей на кадр и 24 млн суммарно; один цикл до 30 секунд; задержка кадра 10–10 000 мс | Animated WebP до 1600 px, сохранённые интервалы и loop, отдельный статичный WebP-постер |
| MP4/WebM | 32 MiB; до 60 секунд, 60 FPS, 3600 кадров; сторона до 4096, до 8 294 400 пикселей на кадр и 4 млрд суммарно декодированных пикселей | H.264 MP4 до 1280×1280 и 30 FPS, AAC при наличии аудио, статичный WebP-постер |

Ограничения декодирования проверяются до и после обработки. FFmpeg принимает только локальные файлы поддерживаемых контейнеров; внешние URL не скачиваются. Слишком сложный или повреждённый файл отклоняется, а не превращается молча в первый кадр. Одновременно допускается один upload от чтения тела до S3/БД; при занятости ответ 503 с `Retry-After: 3` без расходования upload-квоты. Тяжёлая обработка ограничена временем; 422 `MEDIA_PROCESSING_TIMEOUT` предлагает уменьшить файл.

`GET/HEAD /media/{32-base64url-id}.webp` и `.mp4` поддерживают ETag / `If-None-Match`, одиночный `Range`, `If-Range`, 206 и 416 с `Content-Range`. URL остаются immutable; старые WebP-ссылки не меняются. Серверный MIME фиксирован как `image/webp` / `video/mp4`, включён `nosniff`.

`POST /articles/{id}/reports`, JSON `{ "reason": "spam", "details": "optional explanation" }`. Причина: `spam`, `illegal`, `harmful`, `copyright` или `other`; пояснение до 2000 символов. Ответ 201 `{ "received": true }` означает приём жалобы, а не удаление статьи или итог рассмотрения.

## Видео по URL

Документ версии 1 поддерживает отдельный атомарный узел `video` без дочерних узлов, текста или marks:

```json
{
  "type": "video",
  "attrs": {
    "provider": "youtube",
    "src": "https://www.youtube-nocookie.com/embed/jNQXAC9IVRw"
  }
}
```

Редактор принимает обычный URL видео и приводит его к canonical representation. Независимый API-клиент должен выполнить то же преобразование: сервер принимает только согласованную пару `provider` / `src`.

| provider | Canonical src |
| --- | --- |
| youtube | `https://www.youtube-nocookie.com/embed/{11-character-video-id}` |
| vimeo | `https://player.vimeo.com/video/{numeric-id}` |
| rutube | `https://rutube.ru/play/embed/{32-lowercase-hex-id}/` |
| file | HTTPS URL файла `.mp4`, `.webm` или `.ogv` либо `/api/v1/media/{32-char-id}.mp4`; необязательный `posterSrc` — строгий локальный `.webp` URL |

Произвольные iframe HTML, `javascript:` / `data:` URL, несовпадение provider с адресом и обычные URL провайдера вместо canonical src возвращают 400 `INVALID_DOCUMENT`. Публичная статья рендерит провайдера как sandboxed iframe, прямой файл — как `<video controls playsinline preload="metadata">`. Сервер не скачивает видео по URL и не выполняет HTML пользователя. Доступность стороннего плеера, файла и воспроизведения зависит от провайдера и сети читателя.

## Лимиты и ошибки

Заголовок после trim — не более 240 UTF-16 символов. JSON создания и обновления статьи — до 2 MiB (остальные endpoints сохраняют свои меньшие лимиты); документ — до 10 000 узлов, глубина до 32, общий текст до 500 000 символов. Поддерживается `schemaVersion: 1`.

Форма ошибок: `{ "error": { "code": "…", "message": "…" } }`.

| HTTP | code | Действие клиента |
| --- | --- | --- |
| 400 | INVALID_INPUT | Исправить данные; не повторять неизменный запрос |
| 400 | INVALID_URL | Указать публичный HTTPS URL, разрешённый политикой preview |
| 400 | INVALID_DOCUMENT | Исправить пустой документ или неподдерживаемое форматирование |
| 401 | UNAUTHORIZED | Проверить наличие и правильность ключа |
| 404 | NOT_FOUND | Статья отсутствует либо недоступна |
| 409 | VERSION_CONFLICT | Получить свежую версию, сохранить локальные изменения |
| 413 | PAYLOAD_TOO_LARGE | Уменьшить документ или файл |
| 415 | UNSUPPORTED_MEDIA_TYPE | Выбрать настоящий поддерживаемый файл |
| 422 | PREVIEW_UNAVAILABLE | Вставить обычную ссылку либо повторить позже |
| 422 | MEDIA_PROCESSING_TIMEOUT | Уменьшить длительность, разрешение или сложность файла |
| 429 | RATE_LIMITED | Соблюсти `Retry-After`, не запускать частые повторы |
| 503 | PREVIEW_BUSY | Соблюсти `Retry-After: 3`; не запускать параллельные повторы |
| 503 | UNAVAILABLE | Сохранить черновик и повторить позже |

Для web fetch не требуется отправлять cookie авторизации. HTTPS обязателен. Авторский ключ должен находиться в secure storage мобильного клиента и IndexedDB веб-клиента; его экспорт — отдельное осознанное действие пользователя.

## Анимация в canonical документе

Документы остаются `schemaVersion: 1`. У `image` появились необязательные атрибуты `animated: boolean` и `posterSrc`. Постер допускается только по строгому локальному WebP пути. Для локального видео используются `{provider: "file", src: "/api/v1/media/<id>.mp4", posterSrc: "/api/v1/media/<poster>.webp"}`. Старые атрибуты изображений и видео принимаются без массовой миграции содержимого. Старые GIF, ранее преобразованные в статичное изображение, нужно заново загрузить из оригинала: потерянные кадры восстановить невозможно.

## Время чтения и прочтения

Публичная статья дополнительно возвращает `readingMinutes` (текст canonical документа / 200 слов в минуту, округление вверх, минимум 1) и `showViewCount`. `viewCount` возвращается только при `showViewCount: true`. Время чтения приблизительно и включает текст таблиц и кода.

`showViewCount?: boolean` принимается при POST и авторском PATCH: по умолчанию true на создании, при пропуске в PATCH сохраняется прежняя настройка. Она защищена тем же ключом и optimistic version, сохраняется в локальном черновике и JSON-экспорте. Просмотры не меняют publication version или updatedAt.

`POST /articles/{id}/views`, явный допустимый `Origin`, JSON `{}` до 128 байт → `{counted: boolean, viewCount?: number}`. Читатель вызывает его после пяти непрерывно видимых секунд, а не при SSR, GET, OG, prefetch или открытии редактора. Скрытый счётчик продолжает суммировать, но число не возвращается. Сетевой сбой статистики не блокирует чтение.

Браузер хранит в sessionStorage только timestamp статьи, без visitor ID/cookie/fingerprint. На сервере новый механизм использует короткоживущие HMAC-токены статьи/сети/фиксированного окна 30 минут; отдельный бюджет 120 запросов на 10 минут ограничивает злоупотребления. Токены удаляются раз в минуту после инициализации подсчёта, включая простой работающего процесса. При остановке приложения удаление возобновится после запуска и первого подходящего запроса; уже истёкшие токены не влияют на новое окно. В backup записи могут сохраняться в пределах его retention. Действующая общая защита других API по IP-HMAC не заменяется.

Известные боты и предпросмотры отсеиваются, но это не доказательство отсутствия всех ботов. Общий IP может объединять читателей, а граница окна — допустить дополнительное прочтение. Это агрегированные приблизительные прочтения, не уникальные посетители. Текущая версия не добавляет социальные функции или рекламную аналитику.


## Приватная история публикации

Все операции требуют `Authorization: Bearer <editKey>` именно этой статьи. Публичный GET историю не раскрывает; ответы истории используют `Cache-Control: no-store`.

- `GET /articles/{id}/history` → `{ "versions": [{ "version": 2, "title": "Previous title", "createdAt": "2026-10-18T00:00:00.000Z" }] }`. Список предыдущих версий идёт от новых к старым; текущее состояние получают обычным GET статьи.
- `GET /articles/{id}/history/{version}` → `{ "revision": { "version": 2, "title": "Previous title", "content": {…}, "schemaVersion": 1, "showViewCount": true, "createdAt": "…" } }`. Имена поля `snapshot` нет.
- `POST /articles/{id}/history/{version}/restore`, JSON `{ "version": 3 }`, где число в теле — **текущая версия публикации**, а число в пути — восстанавливаемая. Ответ `{ "article": {…}, "url": "…" }` содержит новую текущую версию 4.

Обычный PATCH и восстановление атомарно сохраняют прежнее содержимое, заголовок и настройку счётчика. Восстановление сохраняет ID/URL, существующий суммарный счётчик просмотров и промежуточную историю. Конфликт текущей версии возвращает 409, без создания ложного снимка. Ключ владельца, его хеш и внутренний ID в историю не входят.

Хранятся до 50 предыдущих версий и приблизительно 16 MiB содержимого с заголовками на статью. При каждом успешном обновлении также удаляются снимки старше 90 дней; очистка срока выполняется на обновлении, отдельной ежедневной задачи для истории нет. Чтение истории ограничено 120 запросами в час, восстановление делит бюджет 60 изменений в час с PATCH.

## Расширенное форматирование и блоки

Все примеры ниже относятся к полю `content`, а не к произвольному HTML. Неизвестные узлы, marks и атрибуты отклоняются. Общий лимит 500 000 символов включает исходники формул/диаграмм, сноски и текст карточек ссылок. Экранирование HTML и серверная санитизация обязательны независимо от клиента.

| Узел или mark | Поддерживаемые атрибуты и структура |
| --- | --- |
| `paragraph`, `heading` | `textAlign`: `left`, `center`, `right`, `justify`; у heading `level` 1–6 и необязательный стабильный `id` по `^h-[A-Za-z0-9_-]{1,80}$` |
| `underline`, `subscript`, `superscript` | Marks без атрибутов; дополнение к bold/italic/strike/code/link |
| `highlight` | Mark `{ "color": "yellow" }`; палитра `yellow`, `green`, `blue`, `pink`, `gray` |
| `textStyle` | Mark `{ "color": "blue" }`; палитра `red`, `orange`, `yellow`, `green`, `blue`, `purple`, `pink`, `gray`; произвольный CSS не принимается |
| `link` | Безопасный HTTP/HTTPS/mailto/tel URL или внутренний якорь `#h-…`/`#eq-…`; внутренние ссылки остаются в текущей вкладке |
| `codeBlock` | Текстовые дочерние узлы без marks; `language` до 32 символов `[A-Za-z0-9_+#.-]`, `filename` до 120, `lineNumbers` и `wrap` boolean |
| `mathInline`, `mathBlock` | Атомы без дочерних узлов; непустой `latex` до 4000 символов, необязательный `id` `^eq-[A-Za-z0-9_-]{1,80}$`; только block поддерживает boolean `numbered` |
| `mermaid` | Атом с непустым `code` до 20 000 символов; исходник хранится текстом, preview загружается отдельно |
| `footnote` | Inline-атом с `id` по `^[A-Za-z][A-Za-z0-9_-]{0,80}$` и непустым `text` до 4000; повторный ID допускается только с тем же объяснением |
| `tableOfContents` | Атом без атрибутов; оглавление строится из заголовков документа, а номера сносок и обратные ссылки — по порядку появления |
| `callout` | `kind`: `info`, `note`, `tip`, `warning`, `important`, необязательный `title` до 240; один или больше обычных блоков |
| `toggle` | Непустой `title` до 240, необязательный boolean `open`; один или больше вложенных блоков, HTML details/summary |
| `gallery` | `layout`: `grid`, `horizontal`, `single`; от 1 до 30 дочерних image |
| `image` | Прежние src/alt/title/width/height и animated/posterSrc; новые `caption` до 1000, `align`: left/center/right, `thumbnailSrc`, `sourceWidth`, `thumbnailWidth` |
| `video` | Прежние provider/src/posterSrc; новые `caption` до 1000 и `aspectRatio`: `16:9`, `4:3`, `1:1`, `9:16` |
| `linkPreview` | Атом с HTTPS `url`, `title` до 300, `description` до 1000 и необязательным HTTPS `image` |
| `tableCell`, `tableHeader` | `colspan`, `rowspan` 1–100, `colwidth` до 100 целых значений 0–2000, `align` left/center/right, `textAlign` дополнительно допускает justify |

Формулы рендерятся KaTeX с `trust: false`, ограничением раскрытия макросов и размера. Mermaid работает в strict-режиме, а SVG проходит дополнительную санитизацию. Директивы конфигурации, пользовательские стили и внешние действия Mermaid отключены. Дублированные допустимые heading/math ID при рендеринге получают уникальный суффикс, предотвращая коллизии DOM.

### Превью изображений и размеры

`thumbnailSrc` разрешён только вместе с локальным `src`, оба строго `/api/v1/media/{32-base64url-id}.webp`. `sourceWidth` — целое 1–2400, `thumbnailWidth` — целое 1–480; задаются парой и требуют `thumbnailSrc`. Превью не может быть шире оригинала. `width`/`height` остаются размерами отображения и могут меняться при ручном resize.

Сервер создаёт `srcset` только для статичных изображений с известными исходными размерами и `thumbnailWidth < sourceWidth`. Дескрипторы используют фактические `thumbnailWidth` и `sourceWidth`; предположения «превью всегда 480 px» или «width после resize равен ширине оригинала» не используются. Для анимаций статичное превью никогда не подменяет воспроизводимый оригинал через `srcset`. Старые image без этих атрибутов продолжают работать.

## Безопасные карточки ссылок

`POST /link-preview`, JSON `{ "url": "https://example.com/page" }` до 4096 байт → `{ "preview": { "url": "https://example.com/page", "title": "A page", "description": "…", "image": "https://example.com/image.png" } }`. `image` необязателен; возвращается текстовая метаинформация, не HTML страницы. Результат можно сохранить как `linkPreview.attrs`.

Разрешён только HTTPS на порту 443 без credentials, локальных имён и приватных/зарезервированных адресов. Сервер проверяет **все** DNS-ответы, закрепляет выбранный публичный IP для TLS-соединения и заново проверяет каждый из максимум трёх редиректов. Общий таймаут — 4 секунды, HTML — до 256 KiB; сжатые тела отклоняются. Картинки из метаданных разрешаются относительно URL страницы, но сервер их не скачивает.

Лимит — 20 запросов в час на адрес клиента и максимум два одновременных preview на процесс приложения, включая DNS, TLS, чтение тела и редиректы. При занятости возвращается 503 `PREVIEW_BUSY`, `Retry-After: 3`; ожидание в очереди не создаётся. Слоты освобождаются и при успехе, и при ошибках. Недоступные страницы возвращают 422 `PREVIEW_UNAVAILABLE`; клиент может предложить обычную ссылку.
