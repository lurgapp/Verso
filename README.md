# Verso 2.0

Write. Publish. Share. Анонимный редактор и публикация статей от Lurg. Главная страница открывает редактор; после публикации статья доступна по постоянному адресу `/a/{12-character-Base62-id}`. Регистрация и аккаунты не требуются.

Next.js, React, TypeScript strict, TipTap / ProseMirror, PostgreSQL / Prisma и S3-compatible object storage Garage работают как модульный монолит. Содержимое хранится как типизированный документ JSON версии 1. Публичные статьи рендерятся на сервере.

В редакторе форматирование появляется над выделенным текстом. На пустой строке боковая кнопка `+` открывает вставку блоков; камера открывает загрузку изображения или URL с предпросмотром. Видео можно загрузить с устройства (MP4/WebM до 32 MiB и 60 секунд) либо вставить по URL отдельным блоком плеера: поддерживаются YouTube, Vimeo, RuTube и прямые HTTPS-ссылки на видеофайлы. Обычная ссылка в тексте остаётся обычной ссылкой.

## Инструменты письма

Компактная панель над выделением: жирный, курсив, подчёркивание, зачёркивание, ссылки, код и дополнительные стили. Меню `+` находится в поле слева от текста; `/` открывает тот же набор команд с поиском на русском и английском. Доступны заголовки H1–H6, списки, таблицы, код с подсветкой, формулы LaTeX, диаграммы Mermaid, сноски, оглавление, информационные и раскрывающиеся блоки, изображения, галереи и видео.

Блоки можно перемещать мышью и командами вверх/вниз. Для таблиц есть изменение структуры, объединение ячеек, выравнивание, CSV и явная сортировка. Вставка HTML очищается; Markdown, табличный TSV и обычный текст распознаются отдельно. При вставке URL можно выбрать ссылку, карточку или текст.

В меню доступны режим концентрации, пишущая машинка, личная типографика, статистика, цель письма и поиск с заменой. Черновики имеют ограниченную локальную историю; история публикаций защищена ключом автора. Восстановление опубликованной версии создаёт новую версию по прежнему URL.

Импорт: Markdown, HTML, TXT и прежний JSON-черновик. Экспорт: Markdown, HTML, TXT, JSON; PDF через системную печать браузера. Расширенный Markdown содержит обычный читаемый текст и инертный JSON-снимок для обратного импорта без потери свойств. Обычные Markdown-программы не обязаны поддерживать все блоки Verso. Подробная карта возможностей и ограничений — [Verso 2.0](docs/editor-v2.md).

## Анимации и метаданные статьи

GIF, Animated WebP и APNG сохраняются как Animated WebP с отдельным статичным постером. Ограничены размер исходника, кадры, длительность и декодированные пиксели. Читатель может поставить анимацию на паузу; по умолчанию учитывается `prefers-reduced-motion`. MP4/WebM нормализуются в MP4 с ручным запуском и постером. Подробные лимиты — в [API](docs/api.md).

Под заголовком статьи показаны дата, примерное время чтения и агрегированные прочтения. Автор отключает «Показывать просмотры» через меню редактора и сохраняет публикацию. Скрытое число отсутствует и в публичном API. Новая статистика не восстанавливает исторические просмотры и не определяет уникальных людей. Нет лайков, комментариев, рейтингов или идентификатора посетителя в браузере.

## Запуск

```bash
cp .env.example .env
# Заполните .env собственными случайными секретами и PUBLIC_BASE_URL.
python3 scripts/configure-storage.py
docker compose build app migrate
docker compose up -d db storage
docker compose run --rm migrate
docker compose --profile standalone up -d app caddy
```

Точные параметры маршрутизации, миграций и HTTPS описаны в [docs/deployment.md](docs/deployment.md). Для сервера с существующим reverse proxy добавляется отдельный виртуальный хост Verso; работающие сайты сохраняются.

Для локальной разработки нужны Node.js 22+, PostgreSQL 16 и S3 endpoint с настроенным bucket:

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run dev
```

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

Playwright по умолчанию использует установленный Google Chrome и локальный адрес `http://127.0.0.1:3000`. Для другого исполняемого файла задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; для уже работающего окружения — `PLAYWRIGHT_BASE_URL`. E2E создают собственные статьи и удаляют их ключами автора после проверок. Запускайте нагрузочные и злоупотребительные сценарии только в тестовом окружении.

```bash
PLAYWRIGHT_BASE_URL=http://127.0.0.1:33317 npm run test:e2e
```

Результаты и ограничения конкретного запуска приведены в [docs/verification.md](docs/verification.md). Целевые Lighthouse 95+ и WCAG 2.2 AA требуют измерений; наличие кода или успешная сборка не подтверждают эти показатели.

## Владение статьёй

Публикация создаёт отдельный секрет редактирования. Он хранится на устройстве автора в IndexedDB, а сервер сохраняет только проверочное представление. Публичная ссылка не даёт права изменять или удалять статью. Ключ можно экспортировать и импортировать через интерфейс. Экспортированный файл даёт полные права на статью: храните его отдельно и не публикуйте. После очистки браузера, без сохранённого ключа, восстановление доступа невозможно.

Черновики сохраняются локально в IndexedDB с задержкой после ввода и не отправляются на сервер до публикации. Для безопасной работы с несколькими вкладками редактор отслеживает изменения черновика. При редактировании опубликованной статьи сервер сверяет версию и отклоняет устаревшее обновление.

## Изолированные интеграционные проверки

Все тесты с записью запускаются в отдельном локальном окружении. Нужны PostgreSQL с миграциями, Garage и запущенный Verso; значения `.env.example` не являются production credentials. Для новых интеграционных тестов дополнительно требуются явный флаг и loopback-база с именем `verso_test` либо `verso_<suffix>_test`:

```bash
VERSO_ALLOW_ISOLATED_DB_TESTS=1 \
DATABASE_URL=postgresql://verso_test@127.0.0.1:25432/verso_test \
VERSO_TEST_BASE_URL=http://127.0.0.1:33317 \
npm run test:integration
```

E2E по умолчанию запрещает внешний адрес. Разрешать `VERSO_ALLOW_EXTERNAL_E2E=1` можно только для согласованной тестовой установки с отдельным исходящим подключением. Локальные старые E2E используют отдельные TEST-NET заголовки каждого сценария; внешний production proxy всегда перезаписывает их. Это предотвращает расходование пользовательской квоты тестами.
